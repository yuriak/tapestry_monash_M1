# Build the two-site reranker datasets

Each command produces one versioned partition with A and B views. Each institution runs the builder locally using its own authorized sources. Both views are generated to audit the union. Use the designated site's directory for local learning; the pooled upstream workspace contains both views. Only coordinate indexes, configuration and aggregate digests are distributed with this repository.

## Setup and build

Use Python 3.11, Git, Bash and flock on Linux. Install the pinned data/recipe dependencies in an environment of your choice. The default output is under this checkout. Set HF_TOKEN privately or sign in to Hugging Face with your own approved IL-PCSR account before starting IL. The public benchmarks can be built separately.

```bash
uv venv --python 3.11 .venv
export PYTHON="$PWD/.venv/bin/python"
uv pip install --python "$PYTHON" -r configs/reranker/two_site/requirements.txt
bash scripts/reranker/two_site/build.sh evidence_inference
bash scripts/reranker/two_site/build.sh casehold
bash scripts/reranker/two_site/build.sh bioasq
GPUS=4 bash scripts/reranker/two_site/build.sh il_pcsr
```

Only the first cold IL build requires CUDA for the native chunk encoder and candidate freeze. GPUS is the number of locally allocated devices (1–4); four logical shards retain the reference encoding batches. Use the pinned Qwen3-Embedding-4B model and BF16/SDPA. Reference retrieval used four A100s. GPU kernels can affect close ranking ties. The verifier checks the exact frozen candidate IDs and order against aggregate digests and reports drift. Existing authorized preparations can be reused with the layout below and `build.sh DATASET --prepared`. Only trust token/chunk pickle files generated by a trusted local preparation. A repeated build uses the same inputs, checks the materialized files, and leaves completed views in place. DATA_ROOT overrides the default parent directory. Model downloads use the standard model cache. RERANKER_TOKENIZER can point verification to the pinned Qwen3-Reranker-0.6B tokenizer.

SITE denotes the site directory itself. Pass absolute paths when invoking scripts from elsewhere. EI and CaseHOLD use the native name validation for dev. See the [centralized recipe guide](centralized-rerankers.md) for the remaining model/output/config arguments. For CaseHOLD generate preparation and baseline predictions on the same site view before later epoch training. For IL use the il_chunk scripts. Both legal tasks share one case assignment. For mini-BioASQ the reference is the BCE recipe. For EI the 2N and 4N recipes use identical article membership.

## Partition and provenance

The published v1 taxonomy, source aliases, seed 42 and 0.72 preferred-site routing probability are in configs/reranker/two_site/rules.json. A and B are simulated institutions. For each group, the first 64 bits of SHA-256 of seed:dataset:group are compared with the configured site-A probability (0.72, 0.28 or 0.50). Mixed/unclassified and shared sources use 0.50. This is a group assignment, so realized query and supervision proportions vary. Training membership does not depend on held-out model scores.

- **IL-PCSR** uses the released jurisdiction field, which usually names the court. Delhi, Punjab-Haryana, Allahabad and the other northern courts listed in the config preferentially route to A; other regional courts preferentially route to B; Supreme Court is shared. Aliases collapse Uttarakhand/Uttaranchal and the Jodhpur bench of Rajasthan. Cases with identical normalized judgments share a group. Keep all gold relations and chunk selection rows together. Candidate universes remain the authorized 936 statutes and 3,183 precedents. Revision `28a7f9cdd7e9a33126e7025c9ae14bd2119bbc61`. Each site must obtain gated non-commercial research access. No case-level IL manifest or index is shipped.
- **EI 2.0** aggregates intervention cues across all eligible prompts per PMCID, distinguishing pharmacological from procedure/behavioral interventions. Tied informative votes are mixed. The article owns all sentence offsets, prompt IDs and same-article negatives. Sentence boundaries from the reference scientific spaCy preparation are stored as offsets. Local code reconstructs strings from the pinned article files and applies the native span alignment. Revision `a661e8c14f973398380c8865cf2f27a535aaaf6d`.
- **CaseHOLD** uses the citing context to distinguish criminal and civil topics, grouping identical case-folded whitespace-normalized contexts. Keep the five original holdings, source IDs, order and gold position. Revision `acc4532a67e0966e9ed7ec4ca543e8532f983b0c`.
- **mini-BioASQ** uses deduplicated question text to distinguish molecular biology and clinical questions. The 11b-derived subset retains the published test, seed-42 dev, all qrels and 40,181 abstracts. A compressed unsigned-16-bit ordinal index restores the original Top1000 order, including ties, against a checksum-verified sorted ID dictionary. Revision `8a845907dc1cff31d42fa6f7bb9c6eef5f3ae6f6`. Original source terms apply to abstract text and questions.

The three text-based recipes score train-reviewed lexical cues in the config. Strictly larger nonzero scores assign a lexical category. A balanced logistic classifier with unigram/bigram TF–IDF learns from unambiguous training groups only. It refines unknown groups when the maximum class probability reaches 0.65. Mixed or lower-confidence groups retain shared routing. The EI classifier reads all ICO prompts in the article. Site distributions overlap by design. A training group or supervised relation belongs to a single site; sites may access the permitted shared retrieval corpus. Australian/Indian JudicialMind slices and the external Australian Tax evaluation remain separate existing assets.

## Verification and subsequent evaluation

Each dataset directory contains v1/summary.json, v1/checksums.json and per-site index.jsonl (split, query/group, category/reason, site, native reference). Index files with record-level identifiers remain local. The checked-in reference.json binds the complete site memberships and IL/BioASQ ranked candidate lists and qrels. Verify again without generation with:

```bash
PYTHONPATH=src "$PYTHON" -m tapestry_m1.reranker.two_site.verify casehold \
  --root data/two-site/casehold --config configs/reranker/two_site
```

The verifier checks disjoint groups, full split union and native records, then exercises real sampling and tensor preparation on CPU. The optional indices module regenerates the EI offsets or BioASQ ordinal payload from the corresponding frozen preparation; use `python -m tapestry_m1.reranker.two_site.indices --help` with PYTHONPATH=src.

For future experiments, evaluate pretrained, local A, local B, FedAvg and (where authorized) pooled adapters on A, B and the native full evaluation. Select on dev. Merge confusion counts for Macro-F1 and pool sentence scores/labels for EI AUROC where permitted. Use original candidate prefixes and evaluate empty-gold cases per the target metric. For optional transfer use the destination benchmark's instructions, qrels and held-out evaluation.
