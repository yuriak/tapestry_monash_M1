# Frozen base-reranker hard-negative selection

Selection identity `m1.reranker_hard.v1` is an additive training-negative arm of the unchanged [PEFT v2 contract](reranker_training_v2.md). Its own recipe and group/cache manifests pin provenance; historical v1/v2 fixtures and identities remain immutable.

Start with a checksummed source-grouped QA collection, original same-split Top-100 rankings and four-candidate groups. Keep every query/order/split, positive and original random candidate exactly. Score the union of each Top-100 and its original four candidates with the pinned **unadapted** base Qwen3 reranker in eval mode, left padding and the original yes/no serialization. Cache unique query/document raw float32 yes-minus-no logits, token audits and model/config/code/lock/input hashes. Teacher context8192, batch8, BF16/SDPA. Never derive margins from saturated probability inversions.

Select two teacher-highest eligible Top-100 candidates, ties ascending doc ID, excluding the fixed random, all known positives and source aliases, exact/near duplicate positives and candidates incompatible with each other or the random. Do not expand the pool. Preserve assumed/ambiguous labels; teacher preference is not a relevance judgement. Fail before training if counts or fixed identities differ. Only hard candidate records/provenance can change. Difficulty/causal analysis is external research, not a trainer policy.

The single L0 run preserves two epochs, seed20261026, effective8/micro1, optimizer/LoRA/scoring and dev-BCE selection from the original recipe. A bounded preflight compares actual initialized A0/A1 adapter tensors and checks standard save/reload/continuation. Training deliberately checkpoints at5 then independently resumes; 1,805 groups yield452 steps and tails5. Teacher query caches and PEFT checkpoints are immutable resumable units; duplicate stage writers are rejected. Native evaluation reuses frozen original candidates and context8192. No analysis code, raw data, site paths or adapters belong in this source tree.

Run from source with `python -m tapestry_m1.workflows.reranker_hard {preflight,mine,train} CONFIG --data-root DATA --reference-root ORIGINAL_RUN --run-root NEW_RUN` in an appropriate GPU allocation. `mine` writes teacher/group manifests and a comparability gate. `train` revalidates the gate, completes only L0, freezes selection, and evaluates both native benchmarks. Private orchestration must run the research difficulty review between mining and training, and final independent analysis/audit afterward. Each stage writes a status and a complete marker only on success. Keep the managed environment unchanged while a frozen-source job is running.
